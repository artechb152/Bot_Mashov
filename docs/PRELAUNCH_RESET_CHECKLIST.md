# מצפן — רשימת תיוג לאיפוס לפני עלייה לאוויר (Prelaunch Reset Checklist)

מסמך זה מתאר את סדר הפעולות לאיפוס בסיס הנתונים והקמת החשבונות האמיתיים **לפני**
העלייה לאוויר. **אין לבצע איפוס עכשיו.** אין לכלול בקובץ זה סיסמאות אמיתיות.

> כל הפקודות ההרסניות מסומנות ⛔ — הן מתועדות בלבד ואין להריץ אותן ללא אישור מפורש.

---

## 1. גיבוי בסיס הנתונים
לפני כל שינוי, בצע גיבוי מלא של בסיס הנתונים `matzpen`:

```
mongodump --uri "mongodb://localhost:27017/matzpen" --out ./backup/<תאריך>
```

ודא שהגיבוי הושלם והוא בר-שחזור לפני שממשיכים.

## 2. פקודת האיפוס (⛔ לתיעוד בלבד — לא להריץ עכשיו)
האיפוס נעשה על ידי הסיד ההרסני, המוגן ב-`SEED_CONFIRM=yes`:

```
# ⛔ הרסני — מוחק משתמשים, חניכים ותכנים. להריץ רק לאחר גיבוי ואישור.
SEED_CONFIRM=yes npm run db:seed
```

לחלופין, איפוס נקי לחלוטין מתבצע ידנית מול MongoDB. **אל תריץ כעת.**

## 3. אתחול הקורסים
הקורסים נוצרים באופן אידמפוטנטי (ללא כפילויות, ללא איפוס):

```
# ensureCourses() — נקרא אוטומטית על ידי הסיד/הבקאפיל; קפ"ה + מק"סים.
```

ודא שקיימים בדיוק שני קורסים: `kapeh` (קפ"ה) ו-`maksim` (מק"סים).

## 4. יצירת חשבון בעל המערכת האמיתי (platform owner)
צור תחילה חשבון משתמש רגיל (דרך ההרשמה או ידנית), ולאחר מכן קדם אותו ל-root מוסתר:

```
npm run admin:create-root -- --username "<owner-username>" --profile platform_owner
```

הפקודה קובעת: `role=super_admin, isRootSuperAdmin=true, rootProfile=platform_owner,
directoryVisibility=hidden, courseType=null, courseId=null`. החשבון מוסתר מהספרייה
ומחיפוש הנמענים, אך פעולותיו מתועדות ביומן.

## 5. יצירת חשבון מפקד בית הספר (school commander)
צור חשבון משתמש רגיל וקדם אותו ל-root גלוי:

```
npm run admin:create-root -- --username "<commander-username>" --profile school_commander
```

הפקודה קובעת: `rootProfile=school_commander, directoryVisibility=visible` (מוצג עם כתר),
`courseType=null, courseId=null`.

## 6. בוטסטרפ root מוגן
שלבים 4–5 הם היחידים שיוצרים root. **אין נתיב אתר שיוצר root.** הסקריפט אידמפוטנטי,
דורש אישור `PROMOTE`, לעולם אינו מדפיס סיסמאות/גיבובים ולעולם אינו יוצר משתמש חדש.

## 7. הקצאת rootProfile
מוגדר על ידי `--profile` בשלבים 4–5. `rootProfile` אינו ניתן לעריכה דרך אף API/UI —
רק דרך הבוטסטרפ המקומי. ודא ששני ה-roots קיבלו את הפרופיל הנכון.

## 8. הקצאת נראות (visibility)
`platform_owner` → `hidden` · `school_commander` → `visible`. ברירת המחדל נגזרת
מהפרופיל; ניתן לעקוף עם `--hidden`/`--visible`.

## 9. הסרה או השבתה של חשבונות הבדיקה
אין מחיקת משתמשים במערכת. השבת את חשבונות ה-`*.test` (סטטוס `disabled`) דרך
`ניהול משתמשים`, או הסר אותם ידנית מול בסיס הנתונים במסגרת האיפוס. אין להשאיר
חשבונות בדיקה פעילים בסביבת ייצור. מחק את `.local/test-credentials.json`.

## 10. יצירת מחזורים וצוותים אמיתיים
צור את המחזורים והצוותים דרך `מחזורים וצוותים`. ודא: קוד המחזור ייחודי בתוך הקורס,
צוות משויך למחזור, וקורס הצוות תואם לקורס המחזור (נאכף בשכבת השירות).

## 11. בדיקת עשן (smoke test)
התחברות מוצלחת לכל רמה, טעינת דף הבית עם ניתוב לפי תפקיד, וטעינת האזורים המרכזיים
ללא שגיאת 500. ודא: `npm run typecheck && npm run lint && npm run build` ירוקים.

## 12. בדיקות הרשאה
- סגל אינו יכול לפתוח תיק חניך של סגל אחר דרך URL.
- מנהל רואה את **כל** סגל הקורס שלו (courseId), ואינו ניגש לקורס האחר.
- מנהל־על רגיל אינו פותח תיק ניהול של מנהל־על אחר ואינו משנה תפקידים.
- root מוסתר אינו מופיע בספרייה/בחיפוש נמענים אך מתועד ביומן.
- super_admin/root אינם מתבקשים לבחור קורס.

## 13. בדיקת זרימת קודי הרשאה (invites)
צור קוד הרשאת מנהל (מנהל־על), ודא שהוא מוצג פעם אחת בלבד, חד-פעמי, נעול לקורס,
ובר-ביטול. ודא שקוד שנוצל/פג/בוטל נחסם בהרשמה.

## 14. בדיקת הודעות ובקשות
שלח הודעה, ודא הרשאות נמענים והצמד קובץ (MIME + סיומת מאומתות). פתח בקשה, ודא
שאין למבקש אפשרות תגובה עד שגורם מוסמך מגיב, ושאישור/דחייה יוצרים הרשאה/התראה.

## 15. סקירת יומן ביקורת סופית
עבור על `יומן פעולות` וודא שכל פעולת בוטסטרפ/שינוי תפקיד/סטטוס/שיוך/הרשאה/הקפאה
מתועדת עם שחקן, לפני/אחרי וסיבה — וללא סודות (סיסמאות/גיבובים/קודים).

---

### הערות
- הרץ את ביקורת העקביות (קריאה בלבד, ללא שינוי נתונים) לפני ואחרי האיפוס:
  `npm run check:consistency` — ודא: אין super_admin/root עם קורס, אין אי-התאמות
  courseType↔courseId, אין שיוכים כפולים/יתומים.
- אין להריץ את הבקאפיל (`backfill-org`) ללא אישור מפורש (`BACKFILL_CONFIRM=yes --apply`).
- אין לכלול סיסמאות אמיתיות במסמך זה או בכל קובץ שנכלל ב-Git.
