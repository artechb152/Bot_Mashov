# מצפן — בדיקות קבלה ידניות (Manual Acceptance Tests)

מסמך זה מרכז תרחישי בדיקה ידניים לכל רמות ההרשאה ולמודולים החדשים (הודעות,
בקשות, הרשאות גישה, התראות, ארכיון/נעילת מחזורים).

## סיסמאות

הסיסמאות **אינן** מופיעות במסמך זה. הן נמצאות בקובץ המקומי (שאינו נכלל ב-Git):

```
.local/test-credentials.json
```

אם המשתמשים או הנתונים חסרים:

```
SEED_TEST_DATA_CONFIRM=yes npm run dev:seed-test-data          # יוצר משתמשי בדיקה (⚠ מחדש סיסמאות בדיקה)
SEED_COMMUNICATION_CONFIRM=yes npm run dev:seed-communication-data   # נתוני הודעות/בקשות (אדיטיבי, אינו מחדש סיסמאות)
```

> אין להריץ את `dev:seed-test-data` אלא אם נדרש — הוא מגריל מחדש את סיסמאות
> חשבונות הבדיקה. `dev:seed-communication-data` בטוח להרצה חוזרת (אדיטיבי,
> אינו נוגע בסיסמאות ואינו משכפל שרשורים/בקשות).

## 1. סגל — בעל תיק (staff owner)

התחבר כ-`staff.kapeh.1.test`.

1. `תיקי חניך` → פתח חניך שבבעלותך (למשל `[הדגמה] חניך לדוגמה א׳`).
2. ודא: כפתורי **עריכה** ו**מחיקה** מוצגים; ניתן להעלות/למחוק מסמכים.
3. פתח `עריכה`, שנה שדה ושמור — השינוי נשמר.
4. העלה קובץ קטן והורד אותו בחזרה.

## 2. סגל עם הרשאת צפייה (view grant)

הכנה: כ-`staff.kapeh.2.test` הגש `בקשה חדשה` → סוג *צפייה בתיק חניך*, הזן את
מזהה התיק של חניך בבעלות `staff.kapeh.1.test` והזן סיבה. כ-`admin.kapeh.test`
עבור ל-`בקשות` ואשר עם הערה.

התחבר כ-`staff.kapeh.2.test`:

1. פתח את דף החניך שאושר לך → הדף **נפתח במצב צפייה בלבד**.
2. ודא: **אין** כפתור עריכה, **אין** מחיקה, **אין** העלאה/מחיקת מסמכים.
3. תגית "גישת צפייה" מוצגת.
4. נסה לגשת ישירות ל-`/trainees/<id>/edit` → מתקבל 404 (אין הרשאת עריכה).
5. ניתן להוריד מסמך קיים (אם קיים) — צפייה מותרת.

## 3. סגל עם הרשאת עריכה (edit grant)

הכנה: כמו למעלה אך סוג הבקשה *עריכת תיק חניך*, ואישור על ידי מנהל הקורס.

התחבר כמקבל ההרשאה:

1. פתח את דף החניך → כפתור **עריכה** מוצג (אך **לא** מחיקת החניך).
2. פתח `עריכה`, שנה שדה מותר ושמור — נשמר דרך ה-API המאובטח (אותו טופס עריכה רגיל).
3. ודא: **אין** העלאת מסמכים ו**אין** מחיקת מסמכים (הרשאת עריכה אינה כוללת ניהול מסמכים).

## 4. סגל ללא הרשאה (no grant)

## 12. בקשות (requests)

## 13. אישור וביטול הרשאת גישה (grant approval + revocation)

1. אישור בקשת *צפייה/עריכה* (סעיף 12) → יוצר **הרשאת גישה** למבקש + התראה למבקש.

4. לאחר הביטול — המבקש מקבל התראה, ופתיחת התיק דרך קישור ההתראה מחזירה **404** (ההרשאה נבדקת מחדש בשרת).

## 14. התראות (notifications)

3. "סימון הכל כנקרא" מאפס את המונה.
4. לחיצה על התראה מנווטת ליעד; היעד נבדק שוב בשרת (קישור אינו עוקף הרשאה).

## עדכוני קונסולידציה (Consolidation — persistent shell, directory, drawers)

> חשבונות ה-root של הבדיקה נוצרו לפני שדה `rootProfile`. כדי להפעיל כתר/ניווט לפי פרופיל,
> הרץ (מקומית, מוגן): `npm run admin:create-root -- --username commander.root.test --profile school_commander`
> ו-`... --username owner.root.test --profile platform_owner`. פעולה זו גם מאפסת את הקורס
> שנותר על ה-roots (courseType/courseId → null).

### 16. ניווט קבוע (persistent shell)
1. התחבר כ-`admin.kapeh.test`. נווט בין `סקירת קורס` → `הודעות ובקשות` → `משתמשי הקורס`.
2. ודא: **סרגל הצד נשאר קבוע** ואינו נטען מחדש; רק תוכן המסך משתנה. פריט הניווט הפעיל מסומן.
3. אין כפילויות: פריט אחד ל`הגדרות` (רק גלגל השיניים), אחד ל`הודעות ובקשות`, אחד ל`אנשי המערכת`.

### 17. בקרות חשבון + חלון התנתקות
1. בבר העליון — **פעמון ההתראות + מלבן המשתמש (שם, אווטאר, יציאה) בצד ימין**, **גלגל השיניים (`הגדרות`) לבד בקצה שמאל**. אין פריט `הגדרות` בסרגל הצד.
2. לחץ **התנתקות** → נפתח חלון אישור **ממורכז ומעל כל התוכן** (Portal, לא נחתך), נסגר ב-Escape.

### 18. ספריית "אנשי המערכת" (flyout)
1. לחץ `אנשי המערכת` בתחתית הסרגל → הרשימה נפתחת **מעל ה-Sidebar הימני** (מהקצה הימני, מכסה את הסרגל + מעט רחב יותר לרשת). תוכן העמוד המרכזי **אינו זז**, אין גלילה אופקית, וה-Sidebar שמתחת אינו לחיץ. סגירה בכפתור ה-X / Escape / לחיצה מחוץ לפאנל (ללא החשכה כבדה). פס הגלילה בצד **ימין**; שדה החיפוש קבוע בראש ומסנן בזמן אמת.
2. כל משתמש מוצג כ**אריח ריבועי קומפקטי** (אווטאר + אות, נקודת תפקיד עדינה, כתר ל-root) ב**רשת** בתוך כל קבוצה. **Hover/Focus** מגדיל את האריח (מבוטל תחת `prefers-reduced-motion`) ומציג **כרטיס תצוגה** (שם, שם משתמש, תפקיד, קורס) הצמוד לאריח, שנפתח מעל/מתחת לפי המקום ואינו נחתך. Tab מגיע לכל אריח; Enter/Space פותחים פרופיל.
3. כ-`staff.kapeh.1.test` — מוצגים סגל/מנהלי קפ"ה + הנהלת המערכת בלבד; משתמשי מק"סים ו-`owner.root.test` **אינם** מופיעים.
4. **לחיצה** על אריח → **חלון פרופיל ממורכז** (מעל הרשימה; Escape סוגר קודם את הפרופיל, ואז את הרשימה). כפתור `שליחת הודעה` מופיע **רק** ל-Admin ומעלה, ורק לנמען שמותר לשלוח אליו. Staff אינו רואה אותו כלל.

### 18א. שליחת הודעה מפרופיל (send from profile)
1. כ-`admin.maksim.test` → `אנשי המערכת` → פרופיל `superadmin.test` → `שליחת הודעה`.
2. ודא: חלון הפרופיל **וחלון "אנשי המערכת" נסגרים**, מסך כתיבת ההודעה גלוי, ו-`superadmin.test` **כבר נבחר** כנמען. אין Overlay/scroll-lock שנותר.
3. חוזר גם מ`משתמשי הקורס`/`ניהול משתמשים` (כפתור `שליחת הודעה` בעמוד המשתמש).
4. אבטחה: `/messages/compose?to=<id>` עם נמען שאין הרשאה אליו → הודעת שגיאה ברורה, ללא בחירת נמען.

### 19. פאנל התראות (notification popover)
1. לחץ על **הפעמון** → נפתח **פאנל מלבני אנכי מתחת לפעמון** (לא מגירה, לא ניווט, לא מכסה את כל הצד). Escape / לחיצה בחוץ / לחיצה נוספת על הפעמון סוגרים.
2. לחיצה על התראה מנווטת ליעד וסוגרת את הפאנל; המונה מתעדכן. עובד גם ב**עמוד הפתיחה** למשתמש מחובר.
3. **מיקום דינמי** (Portal, `position: fixed`, נמדד מול הפעמון וה-viewport): הפאנל **אינו נחתך** בשום קצה — במיוחד בעמוד הפתיחה שבו הפעמון צמוד לקצה ימין. קצה הפאנל מיושר לפעמון (RTL), רוחבו וגובהו מוגבלים ל-viewport (רשימה נגללת בפנים), והוא **מתעדכן בזמן אמת** בעת שינוי גודל חלון / Zoom / גלילה. בדוק ברוחבים 300 / 375 / 1280 וב-Zoom 80–150%.

### 20. אזור "הודעות ובקשות" מאוחד + השבתת תגובה לבקשה
1. `הודעות ובקשות` — תת-ניווט אחד: דואר (נכנס/נשלחו/טיוטות/ארכיון) + מפריד + `בקשות`. אין קישור בקשות כפול בסרגל.
2. כ-`staff.kapeh.2.test` — פתח `בקשה חדשה`; בשרשור הבקשה **אין** תיבת תגובה עד שגורם מוסמך יגיב.
3. כ-`admin.kapeh.test` — אשר/דחה עם הערה; כעת המבקש רואה תיבת תגובה.

### 21. עמוד כניסה + ניתוב לפי תפקיד
1. פתח `/` מחובר כ-`admin.kapeh.test` → כפתור יחיד **`כניסה למערכת`** שמוביל ל`סקירת קורס`.
2. כ-`superadmin.test` → מוביל ל`סקירת מערכת`; כ-`staff.kapeh.1.test` → ל`בוט חניכה ומשוב`. אין כרטיסים כפולים.

### 22. סינון קומפקטי (filter)
1. `ניהול משתמשים` → כפתור **`סינון`** עם מונה סינונים פעילים; שינוי תפקיד/סטטוס משתקף ב-URL; `ניקוי סינון` מאפס.

### 23. בר עליון + אנימציית פתיחה
1. בכל עמוד מאומת (כולל **עמוד הפתיחה** למשתמש מחובר) — **פעמון + מלבן המשתמש בצד ימין**, ו**גלגל השיניים (`הגדרות`) לבד בקצה שמאל**, מחוץ למלבן המשתמש ובאותו מיקום; אין כפילות ואין מקבץ יחיד שבו כולם צמודים.
2. גלגל השיניים **אינו זז** כשהשם ארוך; מלבן המשתמש **אינו נדחק שמאלה** כשמופיע רכיב נוסף. אין גלילה אופקית ואין חפיפה עם הסרגל.
3. אייקון **היציאה מהחשבון הפוך אופקית** (החץ מצביע שמאלה) — הטקסט נשאר תקין.
4. בעמוד הבוט — `חניך מקושר` נמצא **מימין** לגלגל השיניים, ללא חפיפה (גם בשם חניך ארוך / רוחב בינוני).
5. עמוד הפתיחה — **אנימציית רקע** של נקודות לבנות עדינות מאחורי התוכן; אינה חוסמת לחיצות; מכובדת ל-`prefers-reduced-motion`; המיקום המרכזי של הכותרת והכפתור לא השתנה.
