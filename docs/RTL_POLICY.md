# True RTL — חוזה כיווניות מחייב

**סטטוס: חובה בכל מסך, רכיב ושינוי UI.** מסמך זה מרחיב את [DESIGN.md](../DESIGN.md) וחל על עבודה אנושית ועל עבודה של Claude, Codex וכלי קוד אחרים.

## כלל עליון

**RTL by default; LTR only by documented, explicit exception.**

כל קוד ממשק חדש, תיקון, ריפקטור, רכיב מספריית צד שלישי, תנועה או אייקון נבדקים כאילו המשתמש קורא ופועל בעברית מימין לשמאל. `dir="rtl"` על העמוד הוא רק תנאי ראשון, **לא הוכחה ל-True RTL**.

אם יש סתירה בין ברירת המחדל של ספרייה לבין החוזה — מתקנים את ההתנהגות או בוחרים חלופה. **אין לכפות היפוך גורף** של כל האייקונים, המספרים או האנימציות. ההחלטה היא סמנטית.

### סדר קדימות
1. הוראת משתמש מפורשת לגבי רכיב מסוים, אם היא נגישה, בטוחה ומתועדת.
2. חוזה זה וכללי הנגישות של הפרויקט.
3. `DESIGN.md` וקומפוננטות המערכת הקיימות.
4. הגדרות ברירת המחדל של framework / CSS / ספרייה.

## 1. בסיס ומיקומים

- `<html lang="he" dir="rtl">` חובה בכל האתר. פורטלים (Dialog, Popover, Modal, Tooltip) חייבים לשמור על RTL, כולל כשהם מוצמדים ל-`document.body`.
- הזרימה **מתחילה מימין**: פריט ראשון ברשימה אופקית, ניווט, breadcrumb, tabs, stepper, סדר כפתורים, כרטיסים וטבלאות.
- שימוש ב-CSS logical properties וב-Tailwind logical utilities בלבד: `start/end`, `ps/pe`, `ms/me`, `border-s/e`, `rounded-s/e`, `text-start/end`.
- אין להכניס קידוד פיזי כגון `left/right`, `ml/mr`, `pl/pr`, `text-left/right`, `float-left/right` או `rounded-l/r` ל-UI, למעט החרגה מנומקת. גם `style={{ marginLeft: ... }}` אסור כברירת מחדל.
- לא להשתמש ב-`flex-row-reverse` כדי לתקן כפתור או ניווט שנבנו לא נכון; סדר ה-DOM צריך להיות נכון סמנטית.
- `justify-between` ו-`items-center` לא מחליפים בדיקה של סדר ה-DOM. מיקום הניווט, מגירות, הודעות, אנימציות וצללים נבחן על פי קצה **תחילה/סוף**.
- ב-grid, carousel, scroll-snap, pagination ו-progress: הפריט הראשון מתחיל מימין; מעבר קדימה נע **שמאלה**. יש לבדוק התנהגות בפועל, לא רק CSS.

## 2. טקסט, מספרים וקלט

- טקסט UI בעברית יורש RTL ומיושר ל-`start`. גם placeholder, כותרות, tooltips, validation והודעות מערכת.
- לשמות, טקסט שהמשתמש הזין, תוכן מעורב או מחרוזות לא ידועות: השתמשו ב-`dir="auto"` **על האלמנט המצומצם שמכיל את הטקסט**, או ב-`<bdi>` לשילוב בתוך משפט. אין להכניס `dir="auto"` למעטפת עמוד.
- קטעים עצמאיים שהם במהותם LTR (כתובת URL, כתובת מייל, קוד, מזהה, פקודה, מספר טלפון כשהצגתו מחייבת זאת) יכולים להיות `dir="ltr"` **רק עם הערת `rtl-exception:` שמפרטת למה**.
- ספרות, סימני פיסוק, תאריך, מטבע, סוגריים ותוכן עברי/אנגלי מעורב נבדקים חזותית; לא הופכים ספרות או מפעילים `scaleX` על טקסט.
- שדות קלט שומרים על מיקום נכון של label, placeholder, אייקון חיפוש/ניקוי, שגיאה ו-suffix/prefix. תוכן המשתמש מבודד כיוונית לפי סוג השדה.

## 3. כפתורים, סדר אייקון–טקסט וניווט

- ברכיב `inline-flex` רגיל עם `dir="rtl"`, **הילד הראשון ב-DOM נמצא בצד ימין**. אייקון מוביל (leading) יופיע **לפני** הטקסט ב-DOM; אייקון נגרר (trailing) **אחריו**. לא משתמשים ב-`row-reverse` כפתרון.
- בתוך קבוצה של כפתורים, בדקו מה הפעולה הראשית ומה רצף הפעולות ב-RTL; לא רק את יישור הטקסט.
- כפתור עם אייקון בלבד מחייב `aria-label`; אייקון דקורטיבי ליד טקסט מחייב `aria-hidden="true"`.
- **חזרה / Back:** חץ ימינה (`ArrowRight`). **קדימה / Next:** חץ שמאלה (`ArrowLeft`). באייקון chevron אותו עיקרון: ימינה לחזרה, שמאלה להמשך. העדיפו את `NavigationArrow` המשותף.
- אייקונים לא-כיווניים כגון חיפוש, פלוס, איקס, הורדה, שעון, אזהרה, פרופיל — **לא משקפים אוטומטית**. אייקון ייצוגי כמו לוגו/דגל/תרשים/מספר לעולם לא משתקף בלי הצדקה סמנטית.
- אייקונים שמייצגים תנועה (שליחה, יציאה, כניסה) נקבעים לפי **משמעות הפעולה על המסך**; אם צריך לשקף, עשו זאת נקודתית ולא על כל הספרייה.

## 4. תנועה, הופעה והתנהגות

- קבעו כיוון לפי סמנטיקה: כניסה מה-`inline-start` היא **מימין**; מה-`inline-end` היא **משמאל**. מגירה המוצמדת ל-`start-0` נסגרת אל **ימין** המסך; מגירה בצד `end-0` — שמאלה.
- התקדמות ברצף לימודי, שלבים או carousel נעה **מימין לשמאל**; חזרה בכיוון ההפוך. אין להעתיק באופן עיוור `translateX` או `slide-left` מדוגמת LTR.
- אנימציית hover של חץ או כרטיס חייבת להתקדם בכיוון החץ. אנימציית כניסה/יציאה חייבת להתאים לצד שממנו הרכיב נפתח.
- אנימציות לא-כיווניות (fade, scale, pulse, תנועה אנכית) אינן זקוקות לשיקוף.
- תמיד לכבד `prefers-reduced-motion`. שינוי כיוון לא יכול לבוא על חשבון נגישות או ביצועים.

## 5. אינטראקציה, מקלדת ונגישות

- סדר Tab ומיקוד תואם את **סדר הקריאה החזותי מימין לשמאל**, באמצעות DOM נכון; אין לשנות `tabIndex` כדי לפצות על DOM הפוך.
- עבור tabs/stepper אופקיים: `ArrowLeft` מתקדם לפריט הבא ב-RTL, `ArrowRight` חוזר לפריט קודם, בהתאם לדפוס הווידג'ט ול-WAI-ARIA. יש לבדוק מקרי קצה.
- תפריטים, רשימות נפתחות, popover, tooltip, Dialog, Drawer ו-toast נפתחים ומוצבים ביחס ל-start/end.
- בעת צירוף ספריית צד שלישי: לבדוק תמיכת RTL אמיתית, מיקום פורטלים, מקשים, אנימציות, גלילה וסדר אלמנטים; אם נדרש, לתעד adapter או override ממוקד.
- אין להסתפק בצילום של desktop: לבדוק גם מובייל, overflow, zoom וטקסט ארוך בעברית.

## 6. חריגות מבוקרות — חובה לתעד

לכל `dir="ltr"` או שימוש אחר בכיוון פיזי בממשק, הוסיפו מעל המקום הרלוונטי הערה קצרה עם **`rtl-exception:`** וסיבה ספציפית. לדוגמה:

```tsx
// rtl-exception: invite token is a machine-readable LTR identifier, not Hebrew UI text.
<code dir="ltr">{token}</code>
```

אין להוסיף החרגה כללית לקובץ/תיקייה או לשנות את הסקריפט כדי לעקוף בדיקה. החרגה לא מיועדת לטעויות שאפשר לתקן באמצעות logical properties. שינוי משמעותי בהתנהגות RTL חייב לציין זאת גם בתיאור ה-PR.

## 7. שערי איכות מחייבים

1. לפני commit: `npm run check:rtl`. הבדיקה בודקת בסיס `html`, `dir="ltr"` ללא הסבר, physical Tailwind utilities ו-physical CSS.
2. ב-CI מריצים את אותה הבדיקה על Pull Requests. **בדיקה סטטית לא מאשרת סמנטיקה של אייקונים או אנימציות** — נדרשת בדיקה חזותית וידנית בנוסף.
3. מעבר על המסכים ששונו לפחות ב-**390px, 768px, 1440px**, כולל מצבי טעינה, ריק, שגיאה ותפריטים.
4. לתעד ב-PR: סדר התקדמות, אייקונים, טקסט/מספרים מעורבים, כפתורים, overlays, אנימציות, מקלדת ו-`prefers-reduced-motion`.
5. אם אי אפשר להפעיל את האתר בסביבת הפיתוח — לרשום במפורש שהבדיקה החזותית **לא בוצעה**, ולא להציג זאת כ-RTL מלא ומאומת.

### הגדרת Done

השינוי עומד ב-True RTL רק כאשר המיקום, סדר ה-DOM, הטקסט, האייקונים, התנועה, הכפתורים, המקלדת, מיקום הפורטלים והמצב הרספונסיבי נבדקו. בדיקת קוד ירוקה לבדה **אינה מספיקה**.
